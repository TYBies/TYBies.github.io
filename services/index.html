01 / The pilot

Small scope. Explicit acceptance.

For a small team with an existing app and a manual or inconsistent release process.

What the engagement covers

  1. Review one application's build and test commands.
  2. Prepare Dockerfile and Docker Compose configuration.
  3. Set up GitHub Actions build and test gates with agreed permissions.
  4. Rehearse a release to an isolated staging target and check health.
  5. Rehearse a supported rollback and hand over a short runbook.

Agree the finish line first

A clean checkout builds; a broken test blocks promotion; the agreed staging health check passes; the previous supported version can be restored; you can follow the handover commands.

You provide permission to work on the repository, an app that can be built and tested, and an approved staging environment. Hosting and third-party charges remain yours.

Not included: feature development, Kubernetes or multi-service migrations, production operation/on-call, uptime guarantees, penetration testing or security certification. Database migrations, data recovery, secrets provisioning and compliance need separate assessment. A code rollback cannot undo data changes.

No published price or delivery-time promise: both depend on the agreed app and acceptance checks. This is a planned independent pilot, not an agency team or an expert certification.
